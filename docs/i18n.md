# Internationalization (i18n) Guide

This document describes the multilingual architecture of the leaderboard frontend, and provides step-by-step instructions for adding new languages and translatable strings.

---

## 1. Architecture Overview

The application uses **react-i18next** (v14) and **i18next** (v23) for internationalization. Translations are stored in static JSON files bundled with the application — no runtime translation service or external API is used.

```
frontend/src/
  i18n/
    index.ts              Re-exports config and types
    config.ts             i18next initialization, language persistence
    LanguageSwitcher.tsx  Globe-icon dropdown for language selection
    locales/
      en/
        common.json       Shared UI strings (buttons, errors, filters, etc.)
        leaderboard.json  Page-specific strings (hero, sections, chart, table)
      lb/
        common.json
        leaderboard.json
      fr/
        common.json
        leaderboard.json
      de/
        common.json
        leaderboard.json
      it/
        common.json
        leaderboard.json
      pt/
        common.json
        leaderboard.json
```

### Namespaces

| Namespace | Purpose |
|---|---|
| `common` | Generic UI — buttons, pagination, filters, form validation, theme toggle, footer, language selector |
| `leaderboard` | Page-level content — hero title, intro text, section headings, chart labels, filter panel |

The default namespace is `common`, so `t("table.loading")` resolves from `common`, while `t("leaderboard:hero.title")` explicitly uses the `leaderboard` namespace.

---

## 2. Packages Used

| Package | Version | Reason |
|---|---|---|
| `i18next` | `^23` | Core i18n engine; v23 is compatible with TypeScript 4.x |
| `react-i18next` | `^14` | React bindings; provides `useTranslation` hook and `I18nextProvider` |

> **Note:** i18next v24+ and react-i18next v15+ require TypeScript 5. If you upgrade TypeScript, you can upgrade these too.

---

## 3. Configuration

**`src/i18n/config.ts`** initializes i18next:

- **Default language:** English (`en`)
- **Fallback language:** English (`en`) — any missing key falls back to the English value
- **Persistence:** the selected language is saved to `localStorage` under the key `leaderboard-language`
- **Detection:** no automatic browser-language detection; English is always the default for first-time visitors

```ts
import i18n from "i18next";
import { initReactI18next } from "react-i18next";

i18n.use(initReactI18next).init({
  resources: { /* all locales */ },
  lng: savedLanguage,     // from localStorage, defaults to "en"
  fallbackLng: "en",
  defaultNS: "common",
  ns: ["common", "leaderboard"],
  interpolation: { escapeValue: false },
});
```

**`src/index.tsx`** imports `src/i18n` before `App` to ensure i18next is initialized before any component renders.

- `"Modelltyp"` (filters.modelType) — direct calque from German; a native term may be preferred
- `"Héierverstees"` / `"Liesverstees"` — standard Luxembourgish for listening/reading comprehension, but confirmation from INLL is recommended

### Step 2 — Register in `src/i18n/config.ts`

```ts
// Add these imports
import esCommon from "./locales/es/common.json";
import esLeaderboard from "./locales/es/leaderboard.json";

// Add to resources object
resources: {
  // ... existing languages ...
  es: { common: esCommon, leaderboard: esLeaderboard },
},
```

### Step 3 — Add to the supported languages list

In `src/i18n/config.ts`, add the entry to `SUPPORTED_LANGUAGES`:

```ts
export const SUPPORTED_LANGUAGES = [
  { code: "en", nativeName: "English" },
  { code: "lb", nativeName: "Lëtzebuergesch" },
  { code: "fr", nativeName: "Français" },
  { code: "de", nativeName: "Deutsch" },
  { code: "it", nativeName: "Italiano" },
  { code: "pt", nativeName: "Português" },
  { code: "es", nativeName: "Español" }, // ← new entry
] as const;
```

That is all. The `LanguageSwitcher` reads from `SUPPORTED_LANGUAGES` and will automatically include the new language in the dropdown.

## 6. Using Translations in Components

### Basic usage

```tsx
import { useTranslation } from "react-i18next";

const MyComponent = () => {
  const { t } = useTranslation("common"); // or "leaderboard"
  return <button>{t("table.cancel")}</button>;
};
```

### Cross-namespace usage

```tsx
const { t } = useTranslation(["common", "leaderboard"]);
// Access with explicit namespace prefix:
t("leaderboard:hero.title");
t("common:table.loading");
```

### Interpolation

Pass variables as the second argument:

```tsx
t("table.showing", { visible: 5, total: 50 })
// → "Showing 5 of 50 rows"
```

### Pluralization

i18next supports pluralization with `_one` / `_other` suffixes:

```json
{
  "chart": {
    "modelsCount_one": "{{count}} model",
    "modelsCount_other": "{{count}} models"
  }
}
```

```tsx
t("leaderboard:chart.modelsCount", { count: 1 })  // "1 model"
t("leaderboard:chart.modelsCount", { count: 5 })  // "5 models"
```

## 7. Fallback Behavior

If a key is missing in the selected language, i18next automatically falls back to English (`en`). This means:

- A partial translation (e.g., only `common.json` translated) is safe to deploy
- Missing keys will show the English text, not a raw key string
- The fallback chain is: `selected language → en`

## 8. Adding New Translatable Strings

When adding a new feature that introduces user-facing text:

1. Add the English string to the appropriate namespace JSON (`en/common.json` or `en/leaderboard.json`)
2. Use a semantic key, not the English sentence (e.g., `"filters.resetFilters"`, not `"Reset Filters"`)
3. Add the same key to **all other language files** (copy the English value if you don't have a translation yet)
4. Use `t("key")` in the component

Run `npm run validate:i18n` to check for missing keys across languages.

---

## 9. Translation Validation

Run the validation script to detect missing or extra keys:

```bash
cd frontend
npm run validate:i18n
```

The script:
- Compares all language files against the English reference
- Reports missing keys per language
- Reports unexpected/extra keys
- Reports coverage percentage per language
- Validates JSON syntax

## 10. Testing Language Switching

### Manual test checklist

1. Open the app at `http://localhost:3000/`
2. Verify English is the default language
3. Click the globe icon and switch to each language in turn
4. Verify UI text updates immediately without a page reload
5. Reload the page — verify the selected language persists
6. Open DevTools → Application → localStorage → verify `leaderboard-language` key
7. Switch language — verify table filtering/sorting state is preserved
8. Clear localStorage and reload — verify English is the default again

### Fallback test

1. Open `src/i18n/locales/de/common.json` and delete a key (e.g., `"filter.apply"`)
2. Switch to German in the app
3. Verify the deleted key falls back to English without crashing

## 11. Common Mistakes and Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Raw key displayed (e.g., `table.loading`) | Key missing from all language files, including English | Add the key to `en/common.json` |
| English text shown in non-English language | Key missing from the selected language file | Add translation for that key |
| TypeScript error `TS1139` from `node_modules/i18next` | Using i18next v24+ with TypeScript 4 | Use i18next v23 and react-i18next v14 |
| Build error: "Cannot resolve react-is" | Pre-existing recharts peer dependency issue | Install `react-is`: `npm install react-is --legacy-peer-deps` |
| Language not persisting after reload | localStorage not accessible (private window) | Expected — localStorage is blocked in private mode |
| LanguageSwitcher not appearing | i18n not imported before App | Ensure `import "./i18n"` is in `index.tsx` before `App` |
| Interpolation not working | Missing `{{variable}}` in translation string | Check the key in the JSON file uses `{{variable}}` syntax |
